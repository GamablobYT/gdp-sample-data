# property_ops — sample brownfield dbt repository

A small existing dbt project (DuckDB locally and in CI) to try the GDP Onboarding Agent App end to end. Synthetic
data only. Once it is on GitHub with a protected default branch it satisfies readiness checks 3–7:

| Check | What makes it pass here |
| --- | --- |
| 3 dbt project | `dbt_project.yml` (profile `property_ops`); `dbt parse` succeeds |
| 4 AGENTS.md managed block | `AGENTS.md` between the `<!-- bmad:context -->` markers |
| 5 onboarding knowledge | `docs/onboarding/rules/*.md` (front matter), `templates/`, `checklist.yml`, `examples/` |
| 6 BMad config | `_bmad/config.toml`; its output folders exist under `_bmad-output/` |
| 7 CI runs dbt build | `.github/workflows/dbt-ci.yml` (copy of `templates/repository-onboarding/ci-workflow.yml`) |

Checks 1–2 (GitHub App installation with branch protection, Jira link) are done in GitHub and the app.

## Try it

1. Create an empty GitHub repository in an allowed organisation, then from a copy of this folder:

   ```
   git init -b main
   git add .
   git commit -m "Initial property_ops project"
   git remote add origin https://github.com/<org>/<repo>.git
   git push -u origin main
   ```

2. Protect `main` (branch protection rule or ruleset) and install the app's GitHub App on the repository.
3. In the app: link the repository to a Jira project and re-run readiness. Create a source onboarding ticket and
   attach the files from `samples/intake/` (synthetic): `tenants.csv`, `rent_payments.csv`, `properties.xlsx` and
   the CDE list `cde_list.xlsx`.

## Layout

- `models/bronze/` — landing source `raw` (one table per input file, all text) and typed bronze models
- `models/silver/`, `models/gold/` — cleaned entities and consumer aggregates
- `macros/` — warehouse-specific SQL behind `adapter.dispatch`
- `soda/contracts/` — Soda Core 4 contracts (data source name `ticket`, bound by the app's `soda_scan` tool)
- `tests/fixtures/` — synthetic CI rows, one CSV per landing table (generated by the app's `generate_fixtures`)
- `docs/onboarding/` — rules (front matter `id, section, source, interpretation`), templates, checklist, examples

Run outside the app: load `tests/fixtures/*.csv` into the `raw` schema of a DuckDB file (all text), then
`dbt build --profiles-dir <dir>` with a DuckDB profile named `property_ops` (schema `main`).
